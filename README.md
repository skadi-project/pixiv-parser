# Загрузчик оригинальных изображений Pixiv

Небольшая асинхронная CLI-утилита на Rust для скачивания оригинальных изображений выбранного автора Pixiv.

## Установка

1. Установите Rust: <https://rustup.rs>
2. Получите значение cookie `PHPSESSID`:
   - войдите на `pixiv.net` в браузере;
   - откройте DevTools → Application/Storage → Cookies → `pixiv.net`;
   - скопируйте значение cookie `PHPSESSID`.
3. Создайте файл `.env` рядом с `Cargo.toml` на основе [.env.example](.env.example).
4. Заполните в нём значение `SESSION`.
5. Соберите проект:

```bash
cargo build --release
```

## Настройка через `.env`

```env
SESSION=ваше_значение_PHPSESSID
DELAY_MS=300
OUT=downloads
```

Переменные:

- `SESSION` — значение cookie `PHPSESSID`;
- `DELAY_MS` — задержка между запросами к API в миллисекундах;
- `OUT` — корневой каталог для сохранения изображений.

Для каждого автора автоматически создаётся отдельный подкаталог с его ID. Например, при `OUT=downloads` и ID `28480895` файлы будут сохранены в `downloads/28480895/`.

Файл `.env` добавлен в `.gitignore`, поэтому секрет cookie не попадёт в Git. Не публикуйте его и не передавайте другим пользователям.

## Использование

Передайте URL профиля или числовой ID автора:

```bash
cargo run --release -- https://www.pixiv.net/en/users/28480895
```

Или:

```bash
cargo run --release -- 28480895
```

CLI-параметры могут переопределить значения из `.env`:

```bash
cargo run --release -- 28480895 \
  --session другое_значение_PHPSESSID \
  --delay-ms 500 \
  --out ./my-downloads \
  --concurrency 2
```

В этом случае изображения будут сохранены в `./my-downloads/28480895/`.

Параметры:

- `--session` — переопределяет `SESSION`;
- `--delay-ms` — переопределяет `DELAY_MS`;
- `--out` — переопределяет `OUT`;
- `--concurrency` — количество одновременных скачиваний от `1` до `32`, по умолчанию `4`.
- `--resume` — использовать сохранённый план из `.pixiv-manifest.json`, не выполнять новое обнаружение профиля; завершённые файлы проверяются потоковым SHA-256 и размером;
- `--retry-failed` — повторить только сохранённые ошибки разрешения страниц и загрузки файлов, включая работы, выпавшие из последнего tier; новое обнаружение профиля не выполняется. Параметры `--resume` и `--retry-failed` взаимоисключающие.

Если `DELAY_MS` или `OUT` не указаны, используются значения по умолчанию: `300` миллисекунд и `downloads` соответственно.

## Лимиты загрузки

Количество работ выбирается автоматически:

- менее 120 иллюстраций — скачиваются 48 последних;
- от 120 до 300 включительно — скачиваются 96 последних;
- более 300 иллюстраций — скачиваются 192 последние.

Сортировка выполняется по числовому ID работы в обратном порядке. Это приближённый способ выбрать новые работы: ID Pixiv обычно растут со временем, но не гарантируют точный порядок публикации.

Многостраничные работы сохраняются отдельными файлами в каталоге автора. Имена берутся из URL Pixiv CDN, например `12345678_p0.png`.

Итоговая структура каталогов:

```text
OUT/
└── <ID_автора>/
    ├── 12345678_p0.png
    └── 12345678_p1.png
```

## Ограничения и предупреждения

- Автоматизированный сбор данных может ограничиваться Условиями использования Pixiv. Используйте программу только для личного архива и не распространяйте скачанные материалы без разрешения правообладателей.
- Для R-18 и другого закрытого содержимого требуется действующая авторизованная сессия.
- Сетевые ошибки, HTTP `408`, `429` и `5xx` повторяются до четырёх попыток с задержками `1`, `2` и `4` секунды. Постоянные ошибки и неподходящий тип содержимого не повторяются.
- Изображения записываются потоком в `имя_файла.part`, затем переименовываются после успешной записи. При обрыве передачи повторная попытка начинает загрузку заново; при обработанной ошибке временный файл удаляется. После аварийного завершения `.part` может остаться и будет перезаписан при следующей загрузке.
- Ответы без `Content-Type: image/*` отклоняются. Это проверка заголовка, а не проверка формата изображения по содержимому.
- API и CDN используют отдельные HTTP-клиенты: cookie `PHPSESSID` не отправляется клиентом загрузки изображений.
- При первом запуске в каталоге автора создаётся `.pixiv-manifest.json`. Это версионированный план, привязанный к ID автора: в нём сохраняются ID работ, идентичность страниц, URL, статусы `pending`/`completed`/`failed`, размер и SHA-256. Замена манифеста выполняется атомарно после каждого результата загрузки.
- `--resume` не делает новую выборку профиля: он повторно использует план и потоково проверяет каждый завершённый файл. Для старых записей без метаданных файл принимается только после совпадения ненулевого размера с CDN и проверки SHA-256; иначе скачивается заново.
- `--retry-failed` выбирает ошибки из манифеста, в том числе старые работы вне текущего tier, и не выполняет новое обнаружение профиля. Ошибки разрешения страниц также сохраняются для последующей попытки.
- Пути из манифеста принимаются только как безопасные имена файлов без обхода каталогов; секреты и текст ответов сервера в манифест не записываются.
- При повторном запуске уже существующие файлы пропускаются только после проверки целостности.
